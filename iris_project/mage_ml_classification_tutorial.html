1What is Mage?

Mage is an open-source tool for building, running and scheduling data pipelines. You write small pieces of Python (or SQL) called blocks in a notebook-like web editor, and Mage connects them into a pipeline that can run automatically.

Why should an ML student care?

A real ML project is never a single model.fit() line. It is a chain of steps:

Get data → Clean / split → Train → Evaluate → Save results

In a Jupyter notebook these steps are mixed together, run in any order, and hard to repeat. Mage forces each step into its own block, runs them in the right order, checks them with tests, and can re-run the whole thing every night with new data.

QuestionJupyter notebookMage pipeline
Order of executionWhatever order you click cellsFixed by the dependency graph (DAG)
Passing data between stepsGlobal variablesReturn value of one block → input of the next
Checking outputsManual print()Built-in @test functions
Running daily / on new dataNot possible directlyTriggers (schedule, event, API)
Interactive developmentYesYes — each block can be run on its own with a preview

2Core concepts

Five words to remember: Project, Pipeline, Block, DAG, Trigger.

TermMeaningIn our Iris example
ProjectA folder holding all your pipelines, blocks and configiris_project/
PipelineAn ordered set of connected blocksiris_classifier
BlockOne Python/SQL file that does one jobload, prepare, train, save
DAGDirected Acyclic Graph — which block runs after whichload → prepare → train → save
TriggerA rule that runs the pipeline automatically"Run every day at 6 AM"

The main block types

@data_loader

Data Loader

Brings data into the pipeline — from a CSV, database, API or library.

@transformer

Transformer

Changes data — cleaning, feature engineering, splitting, even training a model.

@data_exporter

Data Exporter

Sends results out — to a file, database or cloud storage.

@test

Test function

Written inside any block. Runs automatically after the block and fails the run if an assertion fails.

Mage also has Custom, Sensor, Scratchpad, Chart and dbt blocks — we do not need them for this module.

3Setup

Option A — pip (simplest for a lab)

# inside a fresh virtual environment
pip install mage-ai scikit-learn pandas

# create and start a project called iris_project
mage start iris_project

Open http://localhost:6789 in your browser. The Mage editor appears.

Option B — Docker

docker run -it -p 6789:6789 -v "$(pwd)":/home/src mageai/mageai \
  /app/run_app.sh mage start iris_project

Create the pipeline in the UI

  1. Click Pipelines → New → Standard (batch). Name it iris_classifier.
  2. Click Data loader → Python → Generic (no template). Name it load_iris.
  3. Below that block, add Transformer → Python → Generic named prepare_data. Mage automatically connects it under load_iris.
  4. Add another Transformer named train_model.
  5. Add a Data exporter → Python → Generic named save_results.
  6. Paste the code from Section 5 into each block and press Run (▶) on each, top to bottom.
The right-hand panel shows the dependency tree. You can drag lines between blocks there to change who depends on whom.

5Build the pipeline, block by block

Every block follows the same pattern: import the decorator → write one function → return a DataFrame → (optionally) test it.

Data Loader

Block 1 · load_iris

import pandas as pd
from sklearn.datasets import load_iris

if 'data_loader' not in globals():
    from mage_ai.data_preparation.decorators import data_loader
if 'test' not in globals():
    from mage_ai.data_preparation.decorators import test


@data_loader
def load_data(*args, **kwargs):
    iris = load_iris(as_frame=True)
    df = iris.frame                      # 4 feature columns + 'target'
    print('Rows loaded:', len(df))
    return df


@test
def test_output(output, *args):
    assert output is not None, 'No data loaded'
    assert len(output) == 150, 'Iris must have 150 rows'
Inputnothing (it is the first block)
OutputDataFrame, 150 rows × 5 columns
Test checksdata exists and has 150 rows
The if '...' not in globals() lines are standard Mage boilerplate — Mage generates them for you. They just make sure the decorator is imported.
Transformer

Block 2 · prepare_data

import pandas as pd
from sklearn.model_selection import train_test_split

if 'transformer' not in globals():
    from mage_ai.data_preparation.decorators import transformer
if 'test' not in globals():
    from mage_ai.data_preparation.decorators import test


@transformer
def transform(df, *args, **kwargs):
    df = df.dropna()                     # remove empty rows (safety step)

    train_df, test_df = train_test_split(df, test_size=0.2, random_state=42)

    train_df = train_df.copy()
    test_df = test_df.copy()
    train_df['split'] = 'train'
    test_df['split'] = 'test'

    result = pd.concat([train_df, test_df])
    print('Train rows:', len(train_df), '| Test rows:', len(test_df))
    return result


@test
def test_output(output, *args):
    assert 'split' in output.columns, 'split column missing'
Input dfthe output of load_iris
Outputsame 150 rows + a split column (120 train / 30 test)
Why one DataFrame?A block returns one object; a label column keeps it simple
Transformer

Block 3 · train_model

import joblib
from sklearn.tree import DecisionTreeClassifier

if 'transformer' not in globals():
    from mage_ai.data_preparation.decorators import transformer
if 'test' not in globals():
    from mage_ai.data_preparation.decorators import test

FEATURES = ['sepal length (cm)', 'sepal width (cm)',
            'petal length (cm)', 'petal width (cm)']


@transformer
def train(df, *args, **kwargs):
    max_depth = int(kwargs.get('max_depth', 3))   # pipeline variable, default 3

    train_df = df[df['split'] == 'train']
    test_df = df[df['split'] == 'test'].copy()

    model = DecisionTreeClassifier(max_depth=max_depth, random_state=42)
    model.fit(train_df[FEATURES], train_df['target'])

    test_df['predicted'] = model.predict(test_df[FEATURES])
    accuracy = (test_df['predicted'] == test_df['target']).mean()
    print('max_depth =', max_depth, '| Test accuracy =', round(accuracy, 3))

    joblib.dump(model, 'iris_model.pkl')         # save the trained model
    return test_df


@test
def test_accuracy(output, *args):
    accuracy = (output['predicted'] == output['target']).mean()
    assert accuracy >= 0.8, 'Model accuracy is below 80%'
Input dfoutput of prepare_data
Output30 test rows with a new predicted column
Side effecttrained model saved as iris_model.pkl
Teaching point: the test acts as a quality gate. If someone changes the model and accuracy drops below 80%, the pipeline run is marked failed and save_results never runs — bad results never reach production.
Data Exporter

Block 4 · save_results

if 'data_exporter' not in globals():
    from mage_ai.data_preparation.decorators import data_exporter


@data_exporter
def export_data(df, *args, **kwargs):
    df.to_csv('iris_predictions.csv', index=False)
    print('Saved', len(df), 'predictions to iris_predictions.csv')
Input dfoutput of train_model
Outputnothing returned — writes a CSV file
Where is the file?in the folder where Mage runs (the project root)

In a real project this block would write to PostgreSQL, BigQuery or S3 instead — only this block changes, nothing else in the pipeline.

6How data flows between blocks

Whatever a block returns becomes the first argument of the next block.

# load_iris       return df            ──►  # prepare_data  def transform(df, ...)
# prepare_data    return result        ──►  # train_model   def train(df, ...)
# train_model     return test_df       ──►  # save_results  def export_data(df, ...)
  • Mage saves each block's output to disk. So you can re-run only train_model while experimenting, without reloading data.
  • If a block has two parents, it receives two arguments, in the order of the upstream blocks.
  • **kwargs carries pipeline variables and run information (for example, the execution date).

8Pipeline variables & triggers

Pipeline variables

In the pipeline editor, open the Variables tab on the right and add max_depth = 4. Every block can read it with kwargs.get('max_depth'). Students can now tune the model without editing code.

Triggers — running without clicking

Trigger typeWhen the pipeline runsML use case
ScheduleAt fixed times (hourly, daily, cron)Retrain the model every night on fresh data
EventWhen something happens (e.g., a file lands in cloud storage)Retrain when a new labelled dataset arrives
APIWhen another program calls a URLA web app asks for a retrain on demand

To add one: open the pipeline → Triggers → New trigger → choose type → set frequency → Save and switch it on. The Runs page then shows the history of every run, with logs per block.

Big picture: Load → Prepare → Train → Test → Save, running on a schedule with quality gates, is the core idea of MLOps. Mage gives students that idea with very little setup.

9Student exercises

Exercise 1 · Change the model

Replace DecisionTreeClassifier with LogisticRegression(max_iter=200) in train_model. Re-run only that block. Did the accuracy test still pass?

Exercise 2 · Break the quality gate

Set the pipeline variable max_depth = 1 and run the whole pipeline. Which block fails? Does save_results run? Explain why.

Expected: accuracy drops to about 0.6, test_accuracy fails, and the exporter is skipped.

Exercise 3 · Load from a CSV instead

Download the Iris CSV, put it in the project folder, and change load_iris to use pd.read_csv('iris.csv'). Only one block should change. Why is that a benefit of pipelines?

Exercise 4 · Add an evaluation block

Add a new transformer evaluate between train_model and save_results that prints a confusion matrix using pd.crosstab(df['target'], df['predicted']).

Exercise 5 · Schedule it

Create a Schedule trigger that runs the pipeline every hour. After two runs, open the Runs page and compare the logs.

Quick check questions
